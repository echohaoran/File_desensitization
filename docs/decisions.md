# 关键决策记录

## 2026-08-28：Vue/Tauri Bridge

- 决定：Vue 统一通过 `tauriBridge.js` 调用桌面 command，并保留浏览器运行时判断。
- 决定：不在页面组件中直接访问 Tauri 内部 API，避免桌面和浏览器两套调用逻辑扩散。

## 2026-08-28：桌面 Smoke 页面

- 决定：提供独立 `/desktop-smoke` 页面验证新 command，不把未完成的 Tauri 链路强行接入生产工作流页面。
- 决定：测试页只使用虚构样例，覆盖健康、能力查询、脱敏和还原。

## 2026-08-28：Vue + Rust + Tauri 下一代架构

- 决定：目标架构改为 Vue 3 + Rust + Tauri；现有 Vue + FastAPI + Electron 作为迁移基线，分阶段替换。
- 决定：Rust 负责文件、历史、规则、标记、模型和任务调度；Vue 负责界面、左右预览和人工审核。
- 原因：减少本地文件处理链路和运行时依赖，增强桌面隐私、可迁移性和模型管理能力。

## 2026-08-28：人工确认与左右预览

- 决定：脱敏页面使用左侧原文、右侧脱敏预览；右侧只允许选区操作，不允许直接编辑。
- 决定：规则引擎、Rust 检测和 AI 检测均只生成候选结果，最终必须人工确认。
- 决定：AI 默认关闭，只处理用户在右侧主动框选的内容。

## 2026-08-28：文件标记与跨设备还原

- 决定：使用随机不可读文档 ID。DOCX/XLSX/PDF 在文件底部追加明文标记；JSON、TXT、CSV、Markdown 使用 `.desens-meta` 伴随文件。
- 决定：同机还原可匹配本地历史；跨设备还原必须提供脱敏文件和映射数据，不依赖目标设备历史。
- 决定：PDF 使用专门末尾标记页，避免覆盖原文版式。

## 2026-08-28：脱敏库加密导入导出

- 决定：完整脱敏库导出包含规则、用户标注、历史和映射表。
- 决定：导出包使用 AES-256-GCM 加密，使用 `.p12` + 密码作为解密凭证，SHA-256 仅用于完整性校验。
- 原因：历史映射表含原始敏感值，不能以普通明文 JSON 作为跨设备交付包。

## 2026-08-28：JSON 存储与本地训练

- 决定：第一阶段使用带 schema 版本的 JSON，并通过存储抽象预留未来数据库替换；暂不引入 Redis 作为单机主数据库。
- 决定：模型统一使用 GGUF，不进入 Tauri 安装包；用户可从魔搭社区/Hugging Face 下载或选择本地路径。
- 决定：LoRA 训练为独立设置功能。每个训练任务只绑定一个基础 GGUF，训练开始后不可切换；训练数据来自用户标注。

## 2026-08-28：标记、映射表与加密导出协议

- 决定：每次脱敏生成随机不可读的 `document_id`，格式为 `DESENS-DOC-` 加随机大写字母和数字。
- 决定：映射项使用随机 `marker`，不包含 `PHONE`、`ID_CARD` 等敏感类型名称；映射数据与检测来源、审核状态、原始区间一并保存。
- 决定：DOCX 在正文末尾追加标记区，XLSX 追加 `_DESENS_META` 工作表，PDF 追加专门的末尾标记页；JSON、TXT、CSV、Markdown 使用同名 `.desens-meta` 伴随文件。
- 决定：`.desens-meta` 只保存文档标记、格式、版本和文件校验信息，不保存原始敏感值。
- 决定：完整脱敏库导出包使用 `.dlib` 扩展名；包内数据使用 AES-256-GCM 加密，数据密钥由 `.p12` 证书公钥保护，SHA-256 仅用于完整性校验。
- 决定：跨设备还原支持普通映射表 JSON，也支持 `.dlib` + `.p12` + 证书密码；缺失映射项时执行部分还原并报告失败项。

## 2026-08-28：Tauri 模块与调用边界

- 决定：Vue 仅负责界面、预览、选区、审核和任务状态；Rust 负责文件、文档、规则、历史、模型、加密和训练调度。
- 决定：Tauri command 使用版本化 DTO，统一返回成功数据或结构化错误；不把底层异常字符串直接暴露给前端。
- 决定：文件处理、模型下载和 LoRA 训练等长任务使用统一任务事件，不以 UI 轮询临时文件作为主要进度通道。
- 决定：Rust 代码按 `commands`、`domain`、`application`、`document`、`storage`、`crypto`、`inference` 和 `training` 分层。

## 2026-08-28：Command DTO、错误码与任务事件

- 决定：所有 command 请求使用 `schema_version`，响应统一包含 `success` 和 `request_id`。
- 决定：错误使用稳定 `code`、用户可读 `message`、可选 `details` 和 `retryable`，不直接暴露底层异常或敏感路径。
- 决定：长任务通过 `task-event` 事件流报告 `started/progress/log/warning/completed/failed/cancelled` 状态。
- 决定：进度事件只报告百分比、阶段和脱敏后的消息；不得在日志或事件中输出原文、映射值、证书密码或模型密钥。

## 2026-08-28：第一阶段 JSON 存储实现方向

- 决定：规则、历史、标注、模型和训练任务分别保存为版本化 JSON envelope，不使用一个巨型总文件。
- 决定：所有 JSON 写入采用临时文件、刷新、原子替换；写入失败不得破坏上一个有效版本。
- 决定：使用 Rust `StorageProvider` 抽象隔离存储实现，第一阶段实现 `JsonStorageProvider`，未来可替换 SQLite 或服务端存储。
- 决定：历史映射和证书材料与普通规则配置分离；完整脱敏库导出时才统一加密打包。

## 2026-08-28：统一文档适配器

- 决定：所有格式通过统一 `DocumentAdapter` 接口完成解析、结构化预览、脱敏输出、标记写入和还原。
- 决定：JSON 不修改业务结构，使用 `.desens-meta`；TXT、CSV、Markdown 同样使用伴随标记文件。
- 决定：DOCX 在正文底部追加标记区，XLSX 追加 `_DESENS_META` 工作表，PDF 追加专门末尾标记页。
- 决定：适配器输出结构损失、版式变化或部分还原时必须返回 warning 和结果明细，不得静默降级。

## 2026-08-28：`.dlib` 与 `.p12` 安全协议

- 决定：每个 `.dlib` 导出包独立生成 256 位随机 AES 数据密钥和 96 位随机 GCM nonce，使用 AES-256-GCM 加密规范化数据载荷。
- 决定：数据密钥使用 `.p12` 证书中的 RSA 公钥以 RSA-OAEP-SHA-256 包装；`.p12` 内私钥使用用户密码保护。
- 决定：证书密码仅用于解锁 `.p12`，不参与内容密钥派生，也不写入导出包。
- 决定：`.dlib` 明文头只包含协议版本、算法、证书指纹、随机参数和密文长度；规则、标注、历史和映射均位于加密载荷内。
- 决定：AES-GCM 认证失败、证书指纹不匹配、密码错误或包结构异常时必须终止导入，原包保持不变。

## 2026-08-28：GGUF 模型下载与推理边界

- 决定：模型不随 Tauri 安装包发布，由用户从魔搭社区、Hugging Face 下载，或选择本地 GGUF 文件。
- 决定：下载源通过 `ModelProvider` 抽象，下载过程使用临时文件、断点续传、大小和 SHA-256 校验，成功后原子移动到模型目录。
- 决定：所有 GGUF 在注册前执行格式、架构、元数据、量化、上下文和运行时能力探测；不承诺任意 GGUF 均可推理或训练。
- 决定：推理通过 `InferenceRuntime` 抽象；AI 默认关闭，仅对用户选区调用，并只返回结构化候选结果。

## 2026-08-28：标注数据与 LoRA 训练协议

- 决定：用户标注保存原文片段、字符区间、标签、来源文件指纹和审核状态，并以不可变 dataset revision 进入训练任务。
- 决定：训练通过 `TrainingBackend` 抽象；启动前必须验证 GGUF 是否可转换或是否具有配套训练权重和 tokenizer。
- 决定：每个训练任务固定基础模型 SHA-256、数据集 revision、配置和随机种子，训练开始后不可变更。
- 决定：暂停和恢复依赖检查点；取消任务不得删除已生成检查点，除非用户明确清理。
- 决定：训练产物先作为 LoRA adapter 注册，评估通过后才允许合并/量化为 GGUF 或设为推理模型。

## 2026-08-28：模型评估与候选合并

- 决定：训练、验证和测试数据按来源文件指纹隔离，避免同一文件片段跨集合泄漏。
- 决定：评估至少报告实体级 precision、recall、F1，各标签指标、误报、漏报和推理延迟。
- 决定：规则结果优先保留高确定性结构字段；AI 和规则重叠时合并为带多来源证据的候选，不自动覆盖。
- 决定：所有候选最终均由用户确认；模型晋级只能改变“可选/默认候选模型”状态，不能自动执行脱敏。
- 决定：模型必须通过完整性、兼容性、评估阈值和人工确认后，才能设为当前推理模型。

## 2026-08-28：Tauri 增量迁移起点

- 决定：先建立 `src-tauri` 可运行骨架、domain DTO 和健康检查 command，再按领域逐步迁移旧实现。
- 决定：保留现有 Vue + FastAPI + Electron 链路作为回退和行为基线，直到新链路完成对应验收。

## 2026-08-28：JsonStorageProvider 第一版实现

- 实现版本化 `JsonEnvelope<T>` 和白名单集合路径，避免集合名影响存储路径。
- 实现进程内写锁、临时文件写入、文件刷新和原子替换。
- 当前实现只覆盖基础集合读写；schema 迁移、跨进程锁、备份保留和导入冲突处理仍待后续实现。

## 2026-08-28：Tauri State 接入存储

- 决定：应用启动时在 Tauri `setup` 中按应用数据目录初始化 `JsonStorageProvider`，通过 managed state 提供给 command。
- 决定：第一批 command 先提供通用 `read_collection`/`write_collection`，业务 CRUD 在此基础上实现。
- 约束：command 只传递序列化 DTO，不向 Vue 暴露 provider、绝对路径或底层存储异常。

## 2026-08-28：基础脱敏核心实现

- 决定：脱敏核心只处理人工确认后的 span；Rust 重新验证 UTF-8 边界、范围和重叠。
- 决定：marker 生成随机不可读 ID，Mapping 保存原文、类型、原始区间和 marker。
- 决定：还原对所有 marker 执行替换，缺失项返回列表以支持部分还原，不静默清理未知内容。

## 2026-08-28：Mapping 与 History 持久化顺序

- 决定：`redact_and_persist_text` 先写入独立 mapping JSON，再通过 revision 追加 history 摘要。
- 决定：mapping 文件名只使用受控 history ID，拒绝路径分隔符和任意文件名。
- 约束：mapping 写入或 history revision 写入任一失败，都不能向调用方报告成功完成。

## 2026-08-28：文本适配器第一版

- 决定：TXT、CSV、Markdown 首先复用同一个文本适配器，按行生成稳定 block 和字节区间。
- 决定：输出文件使用 `_desensitized` 后缀并生成 `.desens-meta`，不覆盖源文件。
- 约束：当前适配器仅输出元数据，不把 mapping 原文写入伴随文件；mapping 仍由历史存储负责。

## 2026-08-28：文件指纹绑定

- 决定：`.desens-meta` 保存 source_sha256 和 redacted_sha256，映射和历史使用 document_id 关联。
- 决定：文件指纹只用于关联和完整性校验，不替代加密，不作为密钥或密码。

## 2026-08-28：模型与任务类型落地

- 决定：模型来源、状态和元数据使用 Rust 可序列化类型保存，模型内容仍由受控目录管理。
- 决定：下载、推理、训练和文件处理统一使用任务状态/事件模型，具体后端后续通过接口接入。

## 2026-08-28：本地模型注册

- 决定：本地 GGUF 进入清单前至少检查 magic、可读性、大小和 SHA-256。
- 决定：通过 `register_local_model` 注册，不在注册阶段加载模型或执行推理。

## 2026-08-28：任务管理器第一版

- 决定：使用进程内 `TaskManager` 管理任务快照，先提供创建和查询 command。
- 决定：任务快照只保存状态、阶段、进度和用户可读消息，不保存敏感内容。
- 约束：持久化任务历史、取消/暂停状态和事件广播在具体执行器接入前完成设计。

## 2026-08-28：任务状态更新

- 决定：通过 `update_task` 统一更新任务状态、进度和用户可读消息。
- 决定：未知任务不自动创建；后续 command 必须先通过任务 ID 校验。

## 2026-08-28：任务事件与快照持久化

- 决定：创建和更新任务时同步写入 `tasks` 集合，并发送 `task-event`。
- 决定：事件发送采用尽力通知，核心快照写入失败必须返回错误；事件内容不得含敏感文件或映射内容。

## 2026-08-28：任务启动恢复

- 决定：Tauri setup 启动时加载 `tasks.json` 快照并恢复任务索引。
- 决定：completed、failed、cancelled 为不可逆终态；普通状态更新不得将其改回活动状态。
- 约束：进程恢复不等同于下载/训练恢复，后者仍需要独立检查点和执行器协议。

## 2026-08-28：格式能力显式注册

- 决定：通过 `AdapterCapability` 暴露每种格式的预览、脱敏和还原能力。
- 决定：未迁移的 JSON/DOCX/XLSX/PDF 适配器明确标记待接入，继续保留旧链路作为兼容路径。

## 2026-08-28：基础集合读取接口

- 决定：settings、rules、history 先通过专用只读 command 暴露，内部复用同一集合读取逻辑。
- 决定：写入、删除和导入操作在完成冲突校验与事务语义设计后再开放。

## 2026-08-28：集合写入并发控制

- 决定：通用写入 DTO 支持可选 `expected_revision`；调用方提供时必须匹配当前 revision，否则返回冲突错误。
- 决定：业务专用 CRUD 暂不直接从 `serde_json::Value` 推断 item ID，待领域 DTO 冻结后实现。

## 2026-08-17：跨平台桌面交付

- 决定：采用 Electron 作为 macOS/Windows 桌面壳，并用 PyInstaller 打包 FastAPI 本机后端。
- 决定：LibreOffice 作为可选外部组件，仅 DOCX→PDF 功能要求安装；PDF→DOCX、脱敏和还原不受影响。
- 安全约束：桌面后端只监听 `127.0.0.1` 的随机端口，运行期文件写入应用数据目录，浏览器页面不得直接覆盖应用程序或本机历史。

## 2026-08-17：桌面安装包由 GitHub Actions 发布

- 决定：`main` 的每次推送自动构建 macOS ARM64 DMG 与 Windows x64 MSI 并保留工作流产物；推送与 `package.json` 一致的 `vX.Y.Z` 标签时，自动创建 GitHub Release 并附加安装包和 SHA-256 校验和。
- 原因：PyInstaller 需在目标平台构建，GitHub Actions 能为 macOS 与 Windows 分别提供独立 Runner，避免本机交叉编译和手工上传。

## 2026-08-17：版本更新源可选

- 决定：版本更新窗口允许用户选择 GitHub、Gitee 或 CNB 的 `main` 分支；选择仅保存在当前设备。
- 安全约束：服务端使用固定来源映射，不接收任意 Git 仓库 URL，避免更新检查接口成为外部请求代理。

## 2026-08-14：取消登录与访客模式

- 决定：当前版本无需登录，移除访客/本机模式状态文案。
- 原因：产品定位为开箱即用的本地优先工具。

## 2026-08-14：敏感规则与还原历史在浏览器本地保存

- 决定：使用 `localStorage` 保存自定义规则和最多 20 条脱敏历史。
- 影响：无跨设备同步，不提供多用户隔离；还原可通过历史记录直接完成。

## 2026-08-14：PDF→DOCX 必须输出可编辑内容

- 决定：使用 `pdf2docx` 重建可编辑文字、表格和图片，不接受仅把 PDF 页面嵌入 DOCX 的降级方式。
- 影响：复杂 PDF 的版式可能有轻微差异，用户需要复核；后端依赖 `pdf2docx`。

## 2026-08-17：测试样本必须为虚构数据

- 决定：测试文档只使用公开测试号、保留地址和虚构组织信息。
- 原因：避免将真实个人或业务敏感数据带入代码库与回归流程。

## 2026-08-17：Word 预览采用结构化渲染

- 决定：DOCX 不再以压平纯文本预览；服务端返回段落与表格结构及字符偏移，前端负责展示和交互式脱敏标记。
- 影响：保留常用文本层级和表格布局，且点击标记、人工框选仍使用同一份原文偏移；不承诺在浏览器内像 Word 一样逐像素还原页边距、页眉页脚和复杂浮动对象。

## 2026-08-17：还原必须以当前脱敏文件为输入

- 决定：历史记录只保存本机映射，不直接还原历史中的缓存文本；选择历史后，用户须上传当前脱敏文件。
- 原因：脱敏文件可能已经由 AI 或其他工作流计算、整理或改写，必须以用户当前文件为还原对象。

## 2026-08-17：版本更新使用 CNB 受控流程

- 决定：版本号打开轻量更新窗口，用户可查看 CNB `main` 的最新提交、检查可用更新并前往仓库；不在浏览器中直接改写开发服务器。
- 原因：当前开发环境采用文件同步部署，直接在页面内更新会绕过部署校验且可能影响正在使用的本机历史记录。
# 2026-08-17：版本更新源

- 决定：版本检查优先使用 CNB 仓库 `https://cnb.cool/echohaoran/File_desensitization.git` 的 `main` 分支。
- 实现：后端通过 `git ls-remote` 比较当前提交与 CNB 最新提交；前端仅在 CNB 不可用时回退读取部署站点的 `version.json`。
# 架构与产品决策

## 2026-08-17：桌面发行包压缩与版本说明

- 保持 Electron + PyInstaller 双运行时架构，确保离线脱敏、PDF→DOCX 与 DOCX/XLSX 保格式处理能力不被裁剪。
- 使用 electron-builder `maximum` 压缩、PyInstaller `--optimize 2` 和明确的非运行期模块排除项降低安装器体积；不移除 `pdf2docx` 及其所需依赖。
- Presidio/spaCy 在当前生产依赖及模型配置下是不可用的可选增强，桌面包明确排除其依赖树；中文姓名与地址仍使用现有 jieba、规则和人工复核路径。
- 安装包命名固定为 `desensitization_版本号.格式`，发布说明存放在 `docs/releases/vX.Y.Z.md` 并由发布工作流写入 GitHub Release 页面。
# 2026-08-28：桌面构建资源

- Tauri 使用项目现有盾牌视觉资源生成 RGBA PNG 图标，作为开发构建的默认图标。
- Rust 构建产物目录不纳入版本控制；桌面打包配置仍保持关闭，避免在功能未完成前生成安装包。
### 模型下载交互

- 模型卡片必须提供即时下载状态反馈，进度展示按模型独立维护，不影响其他模型卡片。
### 版本更新入口

- 更新版本按钮不得静默覆盖本地安装或历史数据，改为打开对应来源的最新发布页，由用户下载并安装。
### 脱敏页空间分配

- 上传完成后优先扩大检测结果区域；上传卡片允许手动展开，不丢失文件操作入口。
### 检测结果与预览联动

- 检测结果是人工复核入口；悬浮检测卡片必须同步定位原始值与对应标记，帮助用户确认映射关系。
### 联动触发范围

- 联动 hover 的触发源包含检测卡片、原始内容和脱敏内容三方，避免用户只能从检测列表定位对应片段。
### Hugging Face 下载源

- 默认 Hugging Face 下载域名使用 `hf-mirror.com`；模型路径仍保持 Hugging Face 仓库结构，便于切换源和校验。
### 本地脱敏推荐模型

- 推荐模型限定小于 1B，优先选择具备指令跟随/文本分类辅助能力且存在真实 GGUF 文件的模型；下载页面使用 HF Mirror。
## 2026-08-28：模型下载行为

- 推荐模型按钮必须直接下载 GGUF，不再打开浏览器下载页。
- 下载由 Rust/Tauri 执行，使用临时 `.part` 文件，完成后校验并登记。
## 2026-08-28：复核视图联动

- 复核阶段的检测结果与双侧预览共享文档进度和检测 ID，采用滚动比例同步，避免长文档中 hover 后关联内容不可见。
- 用户滚动检测列表、原始文件和脱敏文件时保持独立；只有 hover 才触发关联内容定位和高亮。
## 2026-08-28：推理模型选择

- 用户只能从已校验并登记的本地 GGUF 清单中应用模型；当前选择持久化，后续 AI 检测读取该选择。

## 2026-08-28：GGUF 推理框架

- 改为采用 Candle，Rust 侧使用 `candle-core` 与 `candle-transformers` 原生加载支持的 GGUF 架构并执行本地推理；不再引入 `llama.cpp` 或 C ABI。
- 模型只生成结构化敏感信息候选；敏感库结果作为基础上下文，规则与模型冲突时保留来源并进入人工审核。
## ADR-20260828-01：隔离 GGUF 推理进程

该隔离方案原用于承载 llama.cpp，现迁移目标改为 Candle；父进程仍通过标准输入传递版本化 JSON 请求，读取标准输出候选结果，失败只返回错误码。敏感文本不写日志、不写临时文件。

## 2026-08-28：地址脱敏粒度

地址规则保留省份和城市，仅将区县/街道/道路/巷/门牌号作为敏感片段替换。前端兼容模式与后端规则保持同一粒度，避免城市信息被整体替换。

## 2026-08-28：版本发布触发

桌面包发布由 `v*` Git tag 触发。三个矩阵任务分别上传构建 artifacts，并将对应 MSI/DMG 附加到同名 GitHub Release；普通分支提交不自动生成发布包。

## 2026-08-28：统一下载结果与按钮反馈

- 所有文件下载入口统一派发 `desens:download-result` 自定义事件，由根组件集中弹窗；成功显示文件名与大小，失败显示原因，避免各页面提示口径不一致。
- 下载前必须校验内容非空，失败时不生成占位文件；禁止在触发下载后立即撤销 Object URL。
- 全局按钮增加即时 Toast 反馈，但已有独立加载态的下载/转换/脱敏/还原/模型操作不再叠加 Toast，避免重复提示。

## 2026-08-31 OOXML 本地闭环与伴随标记

- DOCX/XLSX 的脱敏和还原均以用户上传的原始 ZIP 文档包为基底，只改写包含已确认敏感值的 XML 条目，保留其余结构和资源。
- 未发生实际替换时必须失败，禁止生成“成功”文件。
- 纯文本、JSON、CSV、Markdown 保持业务正文可解析，文件关联元数据独立写入 `.desens-meta`。

## 2026-08-31 历史文件存储采用 IndexedDB

- 映射摘要和 UI 元数据保留在版本化历史列表中，真实脱敏文件 Blob 独立保存到 IndexedDB。
- 该选择避免 `localStorage` 容量限制和 Base64 膨胀，同时允许历史页原样下载复杂格式文件。
- 记录删除与文件删除保持同步；缺少 Blob 时必须失败并提示，不允许回退到文本伪造。
## 2026-08-31 统一使用应用内异步二次确认

- 决定通过根组件事件总线提供统一确认弹窗，不在各页面重复实现，也不使用 WebView 原生确认框。
- 上传确认发生在文件读取前；开始确认发生在任务状态切换前；重置确认发生在状态清理前。
- 取消操作必须保持业务状态不变，并允许用户再次发起同一操作。

## 2026-08-31 还原导出改为前端本地生成

- 根因：Tauri 包内 `/api/text-to-*` 不存在，SPA 回退返回 index.html，导致 Word/Excel 下载得到占位示例文件。
- 决定：TXT/CSV/Markdown 用 Blob 直接生成；DOCX/XLSX 用 JSZip 生成最小真实 OOXML 包，并做 ZIP 签名、非空与内容抽样校验；两种运行环境使用同一本地链路。
- CSV 下载带 UTF-8 BOM，保证 Excel 双击打开中文不乱码；源文件为 CSV 时按 CSV 解析为多列，否则单列包裹。
- 历史搜索与排序只影响展示列表，不改变 localStorage 中的原始记录顺序。
## 2026-08-31 统一桌面发布包命名与平台矩阵

- GitHub tag 发布统一构建 macOS ARM64/Intel DMG、Windows x64 MSI、Linux x64 DEB。
- 发布包采用 `local_desens_系统_架构_<平台>.<格式>`：macOS 双架构保留平台后缀，避免同一 GitHub Release 中同名 DMG 相互覆盖。
- 初次 `v0.1.3` Linux DEB 作业因 Runner 缺少 GTK/GDK 开发依赖失败；改用 Ubuntu 24.04 并显式安装 Tauri Linux 编译依赖。
- 修复发布版本统一提升为 `0.1.4`，Git tag 为 `v0.1.4`。
# 2026-08-31 发布文件命名

- 发布资产使用 `local_desens_<平台>.<格式>`；`系统_架构` 仅作为说明性模板概念，不进入实际文件名。

# 2026-08-31 检测片段视觉标识

- 采用红色双波浪线同时标示原文片段和其脱敏占位符，作为跨面板的常态关联提示；黄色高亮仍只在 hover 联动时出现。
# 2026-08-31 应用图标

- 安装包和前端统一使用用户提供的蓝紫盾牌锁圆角矩形视觉；前端保留透明背景，避免白色底板影响导航栏显示。
- 版本显示以 `package.json` 为单一来源，避免 tag 发布后前端仍显示历史版本。

## 2026-08-31：固定视口与卡片内滚动

- 采用 `#app` / `main` 的 flex 纵向布局和 `min-height: 0`，避免桌面窗口尺寸变化时页面整体被内容撑开。
- 长内容由预览、检测结果、历史等所属容器处理滚动；窄屏工作流允许页面根容器滚动以保证可用性。
- 还原与敏感字段页面采用宽屏双栏、窄屏单栏；设置页面卡片使用相对网格尺寸，避免固定像素宽度挤压内容。
# 模型登记必须包含 tokenizer

GGUF 文件不自带 Candle 所需的 tokenizer 资源。为避免“已登记但不可推理”，模型下载和本地登记均要求同目录存在有效 `tokenizer.json`；下载入口使用已核验的 Qwen2.5 基础模型 tokenizer 地址，并在写入模型清单前完成 JSON 校验。

## 2026-09-01：采用签名 GitHub Release 更新协议

- 决定采用 Tauri 官方 Updater，而非通过比较 Git 分支提交或打开下载页实现“更新”。该协议要求每个更新工件用专用私钥签名，并由内置公钥验证。
- GitHub Release 的 `latest.json` 是平台映射清单：macOS ARM64/Intel、Windows x64、Linux x64 分别指向对应已签名更新工件；签名正文写入清单，私钥只保存在本机受限路径和 GitHub Actions Secret。
- 前端先调用 `check`，再调用 `download` 获取真实字节进度；下载并签名校验完成后，用户明确确认才调用 `install` 和重启。Windows 使用 passive 安装模式，macOS/Linux 在安装后由应用重启。

## 2026-09-01：取消 macOS Intel 发布矩阵

- 决定：GitHub Release 仅构建 macOS ARM64、Windows x64 与 Linux x64；不再构建或发布 macOS Intel DMG。
- 原因：macOS Intel runner 长时间排队会阻塞依赖全部矩阵的 Release 发布，而当前交付范围不需要 Intel 安装包。
- 影响：签名 `latest.json` 移除 `darwin-x86_64`，Intel macOS 客户端不再接收应用内更新。
