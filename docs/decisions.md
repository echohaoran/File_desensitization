# 关键决策记录

## 2026-08-17：跨平台桌面交付

- 决定：采用 Electron 作为 macOS/Windows 桌面壳，并用 PyInstaller 打包 FastAPI 本机后端。
- 决定：LibreOffice 作为可选外部组件，仅 DOCX→PDF 功能要求安装；PDF→DOCX、脱敏和还原不受影响。
- 安全约束：桌面后端只监听 `127.0.0.1` 的随机端口，运行期文件写入应用数据目录，浏览器页面不得直接覆盖应用程序或本机历史。

## 2026-08-17：桌面安装包由 GitHub Actions 发布

- 决定：`main` 的每次推送自动构建 macOS ARM64 DMG 与 Windows x64 MSI 并保留工作流产物；推送与 `package.json` 一致的 `vX.Y.Z` 标签时，自动创建 GitHub Release 并附加安装包和 SHA-256 校验和。
- 原因：PyInstaller 需在目标平台构建，GitHub Actions 能为 macOS 与 Windows 分别提供独立 Runner，避免本机交叉编译和手工上传。

## 2026-08-17：版本更新源可选

- 决定：版本更新窗口允许用户选择 GitHub、Gitee 或 CNB 的 `main` 分支；选择仅保存在当前设备。
- 安全约束：服务端使用固定来源映射，不接收任意 Git 仓库 URL，避免更新检查接口成为外部请求代理。

## 2026-08-14：取消登录与访客模式

- 决定：当前版本无需登录，移除访客/本机模式状态文案。
- 原因：产品定位为开箱即用的本地优先工具。

## 2026-08-14：敏感规则与还原历史在浏览器本地保存

- 决定：使用 `localStorage` 保存自定义规则和最多 20 条脱敏历史。
- 影响：无跨设备同步，不提供多用户隔离；还原可通过历史记录直接完成。

## 2026-08-14：PDF→DOCX 必须输出可编辑内容

- 决定：使用 `pdf2docx` 重建可编辑文字、表格和图片，不接受仅把 PDF 页面嵌入 DOCX 的降级方式。
- 影响：复杂 PDF 的版式可能有轻微差异，用户需要复核；后端依赖 `pdf2docx`。

## 2026-08-17：测试样本必须为虚构数据

- 决定：测试文档只使用公开测试号、保留地址和虚构组织信息。
- 原因：避免将真实个人或业务敏感数据带入代码库与回归流程。

## 2026-08-17：Word 预览采用结构化渲染

- 决定：DOCX 不再以压平纯文本预览；服务端返回段落与表格结构及字符偏移，前端负责展示和交互式脱敏标记。
- 影响：保留常用文本层级和表格布局，且点击标记、人工框选仍使用同一份原文偏移；不承诺在浏览器内像 Word 一样逐像素还原页边距、页眉页脚和复杂浮动对象。

## 2026-08-17：还原必须以当前脱敏文件为输入

- 决定：历史记录只保存本机映射，不直接还原历史中的缓存文本；选择历史后，用户须上传当前脱敏文件。
- 原因：脱敏文件可能已经由 AI 或其他工作流计算、整理或改写，必须以用户当前文件为还原对象。

## 2026-08-17：版本更新使用 CNB 受控流程

- 决定：版本号打开轻量更新窗口，用户可查看 CNB `main` 的最新提交、检查可用更新并前往仓库；不在浏览器中直接改写开发服务器。
- 原因：当前开发环境采用文件同步部署，直接在页面内更新会绕过部署校验且可能影响正在使用的本机历史记录。
# 2026-08-17：版本更新源

- 决定：版本检查优先使用 CNB 仓库 `https://cnb.cool/echohaoran/File_desensitization.git` 的 `main` 分支。
- 实现：后端通过 `git ls-remote` 比较当前提交与 CNB 最新提交；前端仅在 CNB 不可用时回退读取部署站点的 `version.json`。
# 架构与产品决策

## 2026-08-17：桌面发行包压缩与版本说明

- 保持 Electron + PyInstaller 双运行时架构，确保离线脱敏、PDF→DOCX 与 DOCX/XLSX 保格式处理能力不被裁剪。
- 使用 electron-builder `maximum` 压缩、PyInstaller `--optimize 2` 和明确的非运行期模块排除项降低安装器体积；不移除 `pdf2docx` 及其所需依赖。
- Presidio/spaCy 在当前生产依赖及模型配置下是不可用的可选增强，桌面包明确排除其依赖树；中文姓名与地址仍使用现有 jieba、规则和人工复核路径。
- 安装包命名固定为 `desensitization_版本号.格式`，发布说明存放在 `docs/releases/vX.Y.Z.md` 并由发布工作流写入 GitHub Release 页面。
